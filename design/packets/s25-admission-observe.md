## 2. Rulings

1. **The module.** 2.1.296 loads one hooks module per plugin (`claude plugin validate`: "a second entry is refused") and one unmatched hook per event ("session.start registered twice without a matcher"), so `session.ts` stays the plugin's one module and `modules` stays `["./session.ts"]` (amended by the coordinator after act 3). Admission's handlers live in `plugin/hooks/admission.ts` as exported functions, and `session.ts`'s `register` composes them: one `session.start` and one `turn.complete` handler each runs the band's part and admission's part, either part's failure caught so neither skips the other or `next`; the other four hooks are registered once. If one probe under `claude plugin test` shows the engine does not resolve a sibling `./admission.ts` import, admission's code moves into `session.ts` under its own heading instead. Load the `plugin-authoring` skill for the API. It never refuses: every `agent.spawn` and `tool.call` hook returns `next(e)` unchanged, whatever the record call does, and a `.catch` around each record call swallows the failure (one line through the API's log, never thrown). No `deny`, no `fs.write`, `$.store` only `pref.*`, no sibling plugin named. Its hooks: `session.start` records `start` (`interactive`); `session.measure` records `reading` only when `e.changed` holds `rateLimits`; `agent.spawn` records `spawn` with the §3.1 fields and the `usage()` readings; `tool.call` on SendMessage records `resume` (its target id only); `turn.complete` with `agentId` records `done`; `session.end` records `end`. The spawn's prompt and the message's text are never sent.
2. **`admission record`.** `claude-session admission record --session <id>` reads one JSON object on stdin, `{kind, …}`, with kinds `start`, `reading`, `spawn`, `resume`, `done`, `end`, each with a fixed key list (as `ledger.append_chain` does); an unknown kind or key, a bad id (the hooks' `_SID`) or bad JSON exits 2 and writes nothing. It stamps `ts` (UTC, seconds) and `session`, takes `chain` from `CLAUDE_SESSION_CHAIN` in its own environment on `start`, and appends one line to `<config.state_dir>/admission/ledger.jsonl` (dir 0700, file 0600) under one `fcntl.flock` waited for at most 2 s; past that it exits 3 and writes nothing. It writes nothing else.
3. **The sweep.** An `end` line is followed, in the same lock, by one `done` line with `swept: true` for each `spawn` of that session with no `done` (matched by `agentId` or `tool_use_id`, as the module can give them); another session's spawns are untouched.
4. **Rotation.** Inside the lock, before an append: when the ledger's first line is older than 29 hours (24 plus one window), it is renamed `ledger.1.jsonl` (replacing one there) and a fresh file is begun.
5. **Types and timing.** Regenerate the module types the skill describes on 2.1.296 and check each field this module reads against them; the report lists any field missing or renamed, and the module reads such a field defensively. Time the frozen tool's start-up: ten runs of `claude-session rules >/dev/null`, the median and the max in the report; a median over 1 s is filed S4.
6. **Version** 2.0.0a10 in the four places, `test_doctor`'s literal with it.
7. **Tests.** `tests/test_admission.py`: the red `test_record_appends_one_line`; each kind's keys, and a refused key, kind, id and JSON writing nothing; the 2 s lock bound (a held lock: exit 3 within 3 s, nothing written); the sweep, this session only; rotation at 29 hours; the modes 0700 and 0600; nothing written outside `admission/`. `admission.test.ts` with stubs: a measure with `rateLimits` in `changed` makes one record call and one without makes none; `agent.spawn` passes `e` to `next` unchanged when the record call resolves, rejects and times out; SendMessage's `tool.call` records `resume` and calls `next`; `turn.complete` with `agentId` records `done`; no call carries a `prompt` or `message` key. A grep test over `admission.ts`: no `deny`, no `fs.write`. Before the report, the mod's tests run once under `claude plugin test` against `session.ts` as installed (no inline `plugins` option), and every band and admission case reads passed; `claude plugin validate plugin` reads no error.
