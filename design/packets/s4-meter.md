## 1. What the source says (quoted)

§2.2: "The plugin's PostToolUse hook, matcher every tool, is the only reader of the session's spend. It reads `transcript_path` from stdin, parses only the bytes appended since its last run (an offset kept in state), and writes `meter.json`". "a turn is one deduplicated assistant message (`requestId`, `message.id`); context is the last assistant message's `input + cache_creation + cache_read` tokens (occupancy, output excluded)". "Under 80% of both ceilings the hook prints nothing. At the first crossing of `checkpoint_at` it emits one `additionalContext` line, the CHECKPOINT signal ... Past 80% it repeats every tenth tool; past 100% it speaks on every tool with the exit rule". "A hook run with `agent_id` on stdin is a subagent's: it exits silently and writes nothing". "The ledger holds no message content, ever." burn-report, shared: tokens = input + cache_creation_input + cache_read_input + output per deduplicated assistant message; no id counts once; sidechain counted and flagged; `<project>/<session>/subagents/agent-*.jsonl` count in the parent's totals.

## 3. Interfaces (signatures, not prose)

- `meter.py`: `parse(path, state=None) -> Meter | None`; the `Meter` fields, all in `meter.json`: `session_id, turns, sidechain_turns, tokens, context` (last occupancy), `max_context, median_context, model, started, ceilings {context, turns}, window, checkpoint_at, pct_context, pct_turns, zone, ts, transcript {path, inode, size, offset}, signal {crossed, tools_since}, builders [{agent, turns, tokens, max_context}], total {turns, tokens, max_context}` (own plus builders), `builders_source` (`subagents` or `none`). Reparse from 0 when the inode changed or the size shrank; per-message contexts kept in state for the median. Unreadable transcript: None, nothing written. Only `usage`, `requestId`, `message.id`, `message.model`, `isSidechain`, `timestamp` are read.
- `hooks.post_tool_use(payload)`: `agent_id` present, posture `off`, or no meter: `{}`. By D13 on `max(pct_context, pct_turns)`: under `checkpoint_at` nothing; at the first crossing one line `CHECKPOINT: <pct_context>% context (<context>/<ceiling>), <pct_turns>% turns (<turns>/<ceiling>); charter <path>; bring the charter current, commit, then exit`; then every tenth tool; at or past 100% every tool with `EXIT: land the act in flight at a checkpoint, then exit; respawn by default, compact at most once`. Whole stdout at most 400 bytes, `additionalContext` under `hookSpecificOutput`.
- `hooks.user_prompt_submit`: keeps its cadence nudge; adds one line `session: <pct_context>% context, <pct_turns>% turns, zone <zone>` whenever a meter exists and posture is not `off`.
- `hooks.session_end`: keeps the overlay clearing; appends to `<state>/ledger.jsonl` (0600) one line with exactly `LEDGER_KEYS`: `session, project, repo, turns, sidechain_turns, tokens, median_context, max_context, profile, model, sha_at_end, dirty, started, ended, ceilings, zone_at_end, exit_reason, builders, builders_source`; the writer refuses any other key; `exit_reason` is stdin's `reason`.
- CLI: `claude-session status [--json] [--transcript PATH]`: the session's meter as one line (`--json` the file); `--transcript` parses that file once and writes nothing; exit 2 with no meter. `claude-session report [--since YYYY-MM-DD] [--json]`: the ledger as a table, exit 2 when empty in range.
